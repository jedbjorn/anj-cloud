# Client architecture: shared core and platform adapters

One client codebase serves every target (decision #74). The Linux client is
the reference. Code is either **shared** (everything the sync engine,
gateway client and UI need, written once in Dart) or **platform-specific**
(an adapter behind a named interface, plus its native code). The directory
tells you which.

## Layer map

```text
lib/
  main.dart              entry point: the desktop entry (arguments, lock, tray) (shared)
  mobile_main.dart       the Android entry: no arguments, no tray, fixed app-private root (shared)
  core/                  SHARED, platform-neutral Dart
    state/               model, SQLite manifest and operation journal
    local/               RootTree (local tree model, change detection), root identity policy, hash meter, path-key helpers
    sync/                sync engine, worker isolate, schedule, transfers, evictions, recovery, editing
    gateway/             cloud API, DAV client, certificate renewal, device identity,
                         in-process device crypto (DeviceCrypto, strict DER)
    access/              documents provider decisions: app allowlist, stable document ids (Android uses it)
    app/                 ClientController, DesktopLifecycle (close/hide/quit rules), preferences
    ports/               the interfaces platform adapters implement (see below)
  ui/                    SHARED widgets and view models (app.dart holds CloudApp and ClientHome)
  design/                SHARED design tokens (badge palette)
  platform/
    adapters.dart        the one factory: picks the adapter set for the running OS
    watchers.dart        picks the change-watcher factory alone (no Flutter import)
    linux/               LINUX adapters (Dart)
    macos/               MACOS adapters (Dart), spec #31
    windows/             WINDOWS adapters (Dart), a skeleton until spec #32 W2-W5
    android/             ANDROID adapters (Dart), spec #28
    desktop/             SHARED desktop-session pieces of the macOS and Windows adapters (ChannelTray over cloud.anj/tray)
    native/              SHARED FFI binding of the anj_* native boundary (NativeRootFs, EvictionNative, LocalWatcher): any platform exporting native/posix/exports.txt
native/
  posix/                 SHARED POSIX native code (S2): libanj_rootfs.so (Linux, Android) and .dylib (macOS)
                         from rootfs.cc + *.inc; per-OS primitives in compat_linux.h / compat_darwin.h /
                         compat_android.h,
                         per-OS guard (guard_lease.inc / guard_busy.inc) and watch (watch_inotify.inc /
                         watch_fsevents.inc) files; exports.txt (the C ABI); test/ (native boundary test);
                         runner bootstrap header
linux/                   Flutter's Linux runner (GTK); its location is fixed by Flutter
macos/                   Flutter's macOS runner (Swift, Xcode); its location is fixed by Flutter
windows/                 Flutter's Windows runner (Win32), generated by Flutter 3.47.9 (spec #32 W0)
android/                 Flutter's Android runner (Gradle, Kotlin: SyncHost, MainActivity), spec #28 A2;
                         native/android/Android.mk builds native/posix for it
tool/                    Linux packaging, installer/manager and fixtures (unchanged location)
  macos/                 mac-test driver, macOS build/check scripts, guest inventory and cleanup
  windows/               Windows seat recipe: install.ps1 (toolchain), build.ps1, launch.ps1
  windows_seat.sh        host-side driver for the W10C-Testing seat (spec #32 W0)

```

Dependency rule: `core/`, `ui/`, `design/` and `main.dart` depend on
`core/ports/` and never on `platform/<os>/`. They reach a platform only
through `platformAdapters()` in `lib/platform/adapters.dart`, or, for the
sync engine's watcher, `platformWatchers()` in `lib/platform/watchers.dart`:
the engine also runs in pure-Dart processes (the crash fixtures under
`tool/`), where the full adapter set cannot load because it imports Flutter.
Adapters may depend on `core/`. `tool/check_layers.sh` (run by `tool/check.sh`) fails
when shared code imports, exports or includes a part from `platform/<os>/`.

## Interfaces (ports)

| Port (`lib/core/ports/`) | Covers | Linux implementation (`lib/platform/linux/`; `NativeRootFs` and `EvictionNative` in `lib/platform/native/`) | Native / system |
|---|---|---|---|
| `RootFilesystem` | descriptor-relative access to the root and private staging | `NativeRootFs` | `native/posix/rootfs.cc` with `compat_linux.h` (openat2, renameat2) |
| `RootIdentitySource` | volume key, inode and birth time of the root | `NativeRootFs` | `volume_key`, `anj_root_info` in rootfs.cc |
| `ReleaseGuard` | guarded release of owned files (cloud-only, editing, recovery) | `EvictionNative` | `native/posix/eviction.inc` (staging) and `guard_lease.inc` (F_SETLEASE) |
| `ChangeWatcher` | local change notification feeding the engine's queue; tuning as `WatcherSettings` | `LocalWatcher` (`lib/platform/native/`, shared with macOS) | `native/posix/watch_inotify.inc` (inotify; macOS: `watch_fsevents.inc`) and `watch_walk.inc` (stat walk) |
| `ChangeWatcherFactory` | starts a watcher (`changeWatcher`, null when none is usable) and says whether a watch on a filesystem reports changes (`watchReportsChanges`) | `LinuxChangeWatchers`, also reached through `LinuxPlatformAdapters` (network and FUSE magics in `LocalWatcher.silentFsMagic` do not) | statfs `f_type` via `RootFilesystem.fsMagic` |
| `DesktopSession` | profile lock / single instance, tray, window, activation | `LinuxDesktopSession` (`ProfileLifetime`, `StatusNotifierTray`, `NativeWindow`, `ActivationService`) | `native/posix/lifecycle.inc` (flock), D-Bus, GTK runner channel `cloud.anj/window` |
| `ProfileLock`, `TrayControl`, `WindowControl` | parts of `DesktopSession` | `ProfileLifetime`, `StatusNotifierTray`, `NativeWindow` | as above |
| `AutostartControl` | start at login (installer/manager hook) | `ManagerAutostart` | manager `autostart` command, `tool/linux_install.py` |
| `SelfUpdatePort` | in-app update (spec #37): the running build's version, the manager's check and hand-over; shared `DesktopUpdater`, Ed25519 and manifest code in `lib/core/update/` | `ManagerSelfUpdate` (macOS: `MacosManagerSelfUpdate`; Windows: `WindowsManagerSelfUpdate`) | bundle receipt, manager `apply-update` (`tool/linux_install.py`; Windows: `tool/windows_manager`) |
| `SecretStore` | keyring for device key and invitation | `KeyringSecrets` | flutter_secure_storage / libsecret |
| `DesktopLauncher` | open a file, open a folder | `PlatformDesktopLauncher` | url_launcher, root identity check via `NativeRootFs` |
| `RootPlacement` | where a new profile's root goes without a picker, the desktop directory for its shortcut, and whether staging goes in the profile (spec #34 P1-P3) | `XdgRootPlacement` (macOS, Windows: `PickerOnlyPlacement`) | `HOME`, `user-dirs.dirs` as `xdg-user-dir` reads it |
| `RootLocationPolicy` (`root_location.dart`) | where the root may be, checked by the picker before anything is made and by the engine at every start | `AnyRootLocation` (no rule) | macOS: `MacosRootLocation` (statfs) |
| `PlatformAdapters` | the set above, as one factory interface (includes `ChangeWatcherFactory`), plus `deviceLabel()` for pairing | `LinuxPlatformAdapters` | |

`SecretStore` implementations throw `SecretStoreUnavailable` when the store
cannot be used now (macOS: the login keychain is locked, denied or not in
this session); the controller then shows that state with Retry and starts
no worker. Linux's keyring never throws it, so Linux keeps its behaviour.

`platformAdapters()` returns `LinuxPlatformAdapters` on Linux,
`MacosPlatformAdapters` on macOS, `WindowsPlatformAdapters` on Windows,
and throws `UnsupportedError` elsewhere. `platformWatchers()` picks the
same way and gives any other platform `UnwatchedChangeWatchers`.

`RootFilesystem` also answers how stamps and installs work on the platform:

| Getter | Linux | macOS (`MacosRootFs`) | Android (`AndroidRootFs`) |
|---|---|---|---|
| `writeback()` | /proc/sys/vm (#39); `RootTree.vmDirectory` is the test seam | none | none (unreadable in the sandbox) |
| `trustedFsMagic` | ext2/3/4, btrfs, xfs, f2fs, bcachefs | none | as Linux (unused without writeback) |
| `fullVerificationInterval` | null: without writeback every pass hashes every file | null | 15 min: event-driven hashing (#130 (3)) |
| `hardLinks` | true: installs link, the staging name is a free alias | true | false: ordinary installs rename (#123 (2)) |

With event-driven hashing, and a working watcher, an ordinary pass hashes
only the paths the watcher reported (and new entries beneath them); a full
verification hashes every file at start, when the app opens, on
`SyncEngine.requestFullVerification()` (A4: once per background run), after
lost events or a watch-limit fallback, and at most every 15 minutes. After a
pass that found nothing the worker waits for the cloud listing instead of its
2 s timer, and a paused observation compares stat and events, never content.
Where installs cannot link, the staged file is renamed into place and its
record finalized, so staging keeps no copy; `link_file` (copy, then
RENAME_NOREPLACE) remains only for installs whose staged copy must survive.
At start the engine finishes an interrupted rename and removes
`.anj-install-*` copies no record names (#130 (4)).
`tool/android_variant_suites.sh` (run by `tool/check.sh`) runs the
storage-sensitive suites against the host build of the Android boundary
(`-DANJ_ANDROID_BOUNDARY`, `ANJ_ROOTFS_HARDLINKS=0`).

## Android (spec #28 A2)

| Port | Android (`lib/platform/android/`) |
|---|---|
| `RootFilesystem`, `ReleaseGuard` | `AndroidRootFs` over the shared binding; `libanj_rootfs.so` from `native/posix` with `compat_android.h`: a component-by-component `O_NOFOLLOW` walk instead of openat2 (seccomp kills it), `link_file` copies instead of linkat (EACCES); the same 53 exports |
| `ChangeWatcherFactory` | `AndroidChangeWatchers`: the shared inotify watcher; ENOSPC leaves a subtree to the stat audit and asks for one full verification |
| `DesktopSession` | `AndroidSession`: the profile flock; no tray, no activation, window controls do nothing |
| `SecretStore` | `KeystoreSecrets`: an AES key wrapped by a non-exportable Android Keystore RSA key, `resetOnError: false` (#130 (2)) |
| `DesktopLauncher` | `AndroidLauncher`: Open hands the engine's working copy to an app the user picks with a per-document grant (R1); Show in folder opens the Files app at the folder |
| `DocumentsHost`, `AppAccess` (`core/ports/documents.dart`) | `AndroidDocuments` over `DocumentsService` (`core/access/`); runner: `AnjDocumentsProvider.kt`, `DocumentsBridge.kt` |
| `AutostartControl` | `AndroidBackgroundSwitch`: the Background sync switch (A4), the runner's unique periodic WorkManager work |
| `PackageInstallerPort` (A7) | `AndroidPackageInstaller` over `UpdateChannel.kt`: installed and archive facts from `PackageManager` (`GET_SIGNING_CERTIFICATES`, current signers), a `PackageInstaller` session with `USER_ACTION_REQUIRED` whose written bytes are hashed again; Android only, so `mobile_main.dart` constructs it |
| `TransferPolicy` (A7 hook) | `NetworkSettingPolicy`: A4's Wi-Fi-only setting, passed in `mobile_main.dart`; only the update download asks it, checks run on any network (R3) |

The in-app updater (`lib/core/update/`, spec #28 A7) asks the G1 feed
through the worker (`releaseCheck`, `releaseDownload`: beside passes, not
in the command queue, outside the pause gate) over the device certificate.
The download lands in `<cache>/anj-updates/`, is hashed while it streams and
is checked against the installed app (package, signer, versionCode) before
Android is asked anything; any failure removes it and shows the reason.
Under "Wi-Fi only" the policy is asked again every few seconds while the
download runs, and leaving Wi-Fi stops it. The install itself waits, like
the desktop updater's, until `controllerUpdateBlocker`
(`update_blocker.dart`, shared) reports no file moving and no Finish
editing pending, since installing restarts the app.
`tool/android/emu_updater.py` is the emulator proof (row 17). The signer
check compares the package's current signing certificates with the
installed app's exactly, so a release signed with a rotated key (APK
signature scheme v3 lineage) is refused by design: A8's release key must
stay the one key for the app's life, and rotating it needs a spec change.

Release builds (spec #40 R1, A8): `tool/android/release_android.py build`
builds `git archive` of one commit at a fixed path
(`~/.cache/anj-cloud/android-release/src`) for arm64 and x86_64, with
versionCode the commit's `git rev-list --count` and versionName its date and
that count, as for Linux. The commit is stamped into the manifest as
`cloud.anj.source_head`. Gradle signs only when `ANJ_ANDROID_SIGNING` names
the properties file of the VM host keystore
(`~/.local/share/anj-cloud/signing/android/`, 0600, outside every worktree;
otherwise the release build is unsigned) and leaves out the per-build
dependency block, so the same commit gives the same APK bytes.
the deployment profile's `[release] android_signer_sha256` (or an untracked `android/release-signer.sha256`) pins the certificate; `deploy/release.py
publish --target android-arm64` and `release_android.py github-release`
refuse any other. `tool/android/emu_release.py` is the emulator proof:
release N to N+1 through the feed, the install waiting for sync, and a
differently signed APK discarded.

`test/android_boundary_test.dart` builds the Android variant for the host,
runs it under a seccomp filter that kills openat2 and refuses linkat, and
requires the Linux build's refusals and errnos. The runner: release id
`cloud.anj.anj_cloud`; every debug and profile build is the QA build
`cloud.anj.anj_cloud.qa` (#108 Q8); minSdk 31, target 36; backup and device
transfer exclude all app data; one cached FlutterEngine per process
(`SyncHost.kt`). On Android `main()` runs `mobileMain()`: profile
`<files>/anj-profile/default`, root `<files>/anj-cloud`, staging
`<files>/.anj-cloud-<profileId>`, all under the canonical files directory.

### Documents provider and app allowlist (spec #28 A5, decision #127)

The runner's `AnjDocumentsProvider` ("AnJ Cloud", authority
`<applicationId>.documents`, `MANAGE_DOCUMENTS`, tree support with
`isChildDocument`) is a thin forwarder. For each call it identifies the
caller (this app; the system Files app or picker, which holds
`MANAGE_DOCUMENTS`; an app holding a per-document grant for exactly that
document; or any other app by `getCallingPackage()`) and sends the call over
`cloud.anj/documents` to the shared `DocumentsService`, which decides:

- Default: no app has access. An app reaches a folder only through an
  approval in "Apps with access" (package, folder, read-only or
  read-write), whatever it picked in Android's picker. Changes are allowed
  only *inside* an approved folder, never to the folder itself. Approvals of
  a folder and of a subfolder are separate rows.
- Revoke is per app and folder. The provider refuses the next call at once,
  and the platform tree grants the app can no longer use are withdrawn
  (`revokeUriPermission(package, uri, flags)`). A descriptor already handed
  out stays open until the app closes it (A1 R2).
- Document ids (`n:<id>`) are allocated once per path, never reused, and
  follow rename and move. They live in `<profile>/app-access.sqlite` with
  the approvals, beside the manifest, never in it. `w:<name>` ids are editor
  working copies and are reachable only with a per-document grant.
- Listings come from the engine's projection. Every open and change is a
  sync-worker command (`DocumentsOps`): a confined read-only descriptor
  that the runner reopens through `/proc/self/fd` with the app's mode,
  exclusive creates (`anj_create_file`), no-replace renames and moves, and
  deletes through the deletion intent. Decision #120 names are refused.
  Every descriptor is recorded in `OpenDocuments`, and
  `RegisteredReleaseGuard` refuses release of an open file. This is defence
  in depth behind `F_SETLEASE`.

- Approvals bind to a folder's path and its local identity. A rename or
  move through the provider or the app keeps both. A different folder that
  later sits at an approved path does not inherit the approval. A folder
  renamed on another device arrives as a removal plus a new folder, so its
  approval ends after the five-minute grace (fail closed) and the user
  approves the new name.
- A read-write approval of a folder covers its subfolders, even one
  approved read-only; the screen says so.
- Apps that share a Linux UID are one identity to the platform: each can
  name any package of that UID as its calling package, so an approval for
  one of them reaches all of them.
- An open answered after the provider's caller gave up (cancel, deadline)
  is closed and reported closed (`PendingCall`). The runner waits 660 s for
  an open, longer than Dart's 600 s, after which Dart itself closes a late
  descriptor.

Package visibility: a `<queries>` entry for launcher activities lists the
apps the user can approve. `QUERY_ALL_PACKAGES` is not requested, and an app
that calls the provider is visible anyway.

The runner (`android/`): release id `cloud.anj.anj_cloud`; every debug build
is the QA build `cloud.anj.anj_cloud.qa` (#108 Q8). minSdk 31, target and
compile SDK 36. Backup and device transfer exclude all app data. The
Application owns one cached FlutterEngine (`SyncHost.kt`) that runs the Dart
entry and with it the sync worker; the activity attaches to it and never
destroys it. On Android `main()` runs `mobileMain()`: the profile is
`<files>/anj-profile/default`, the root `<files>/anj-cloud` and its staging

## Windows (spec #32)

W0 adds the runner, the build recipe and a skeleton adapter set, enough for
the shared app to draw its first frame on Windows. Every Windows port whose
real adapter belongs to a later unit throws an `UnsupportedError` naming that
unit instead of running a weaker stand-in:

| Port | Windows today (`lib/platform/windows/`) | Real adapter |
|---|---|---|
| `RootFilesystem`, `RootIdentitySource`, `ReleaseGuard` | refuses | W2: `anj_rootfs.dll` from `native/windows/` |
| `ChangeWatcherFactory` | `WindowsChangeWatchers`: no watcher, so the stat scan runs | W2: `ReadDirectoryChangesW` |
| `DesktopSession` | `WindowsDesktopSession`: an exclusive `LockFileEx` lock on `<profile>\.anj-cloud.lock`, no tray (Close quits), no activation | W3: no-sharing lock file, activation pipe, notification-area icon, `cloud.anj/window` |
| `SecretStore`, `DesktopLauncher` | refuse | W3: DPAPI, Windows shell |
| `AutostartControl` | refuses | W5: the Windows manager's Run value |

Because the root filesystem refuses, `ClientController.initialize` stops
before it touches the profile, and the window shows the shared "Client
setup could not start" message.

The runner (`windows/`) is Flutter's template with the product title, the
Harbor icon and `longPathAware` in `runner.exe.manifest`. The build needs
Visual Studio Build Tools 2022 with the C++ workload and C++ ATL (for
`flutter_secure_storage_windows`); `tool/windows/install.ps1` installs both
and Flutter 3.47.9 on the seat. From the VM host:

```text
tool/windows_seat.sh start                       # preflight, start, take the lease, wait for SSH
tool/windows_seat.sh ps tool/windows/install.ps1 # only after a seat reset
tool/windows_seat.sh push                        # tracked apps/client files -> C:\anj\work\client
tool/windows_seat.sh ps tool/windows/build.ps1   # doctor, pub get, analyze, tests, release build
tool/windows_seat.sh ps tool/windows/launch.ps1  # console-session launch; then screenshot, launch -Action stop
tool/windows_seat.sh pull 'C:\anj\evidence\w0' <halo-dir>
tool/windows_seat.sh stop                        # ACPI shutdown, wait for "shut off", drop the lease
```

The seat is shared with other projects and with every anj lane, all as the
same the VM host user. Set `ANJ_WIN_OWNER` to your lane tag (e.g. `w2`); there is
no default. `start` records the boot it started (domain UUID, `virsh domid`,
the qemu process start time, the VM host boot id) and its owner as a lease under
`~/.local/share/anj-cloud/state/`. Every guest command and `stop` refuse a
running domain that lease does not match, or a lease another lane owns.
`start` and `stop` serialize on a `flock`. A seat left running without a
valid lease is recovered with `stop --force-unleased`: alone it prints the
qemu process (with this boot's qemu start time), any stale lease and the SSH
sessions to the guest; given that qemu start time it ACPI-shuts down,
refusing with a non-default `ANJ_WIN_LEASE_DIR`, a valid lease or an SSH
session. The owner tag is self-declared, so the lease is a cooperative
guard: never set `ANJ_WIN_OWNER` to another lane's tag.
`tool/test_windows_seat.sh` (run by `tool/check.sh`) tests the script
with fakes, without a VM.

Device crypto is shared code, not a port. `DeviceCrypto`
(`core/gateway/device_crypto.dart`) covers P-256 key generation, the PKCS#8
key PEM, the PKCS#10 CSR, SPKI fingerprints, X.509 parsing and client-chain
verification against the pinned issuer; `DartDeviceCrypto` implements it in
pure Dart on `pointycastle`, with strict DER in `der.dart` (spec #28 U1). No
client code runs the OpenSSL CLI (`test/no_openssl_cli_test.dart`).
`DeviceIdentity` and `CertificatePickup` take a `DeviceCrypto`, so a later
platform keystore can supply its own without changing callers; the key itself
still lives as PEM in `SecretStore`.

The native library keeps its C ABI: the `anj_*` exports of
`libanj_rootfs.so` and the FFI symbol names bound in `native_root_fs.dart`,
`eviction_native.dart`, `local_watcher.dart` and `profile_lifetime.dart`.

## Media fetch (spec #42 F4)

The Downloader's client core is shared code with no port.
`core/gateway/fetch_api.dart` holds the job row (`FetchJob`, `FetchState`
with `unknown` for states a newer gateway adds), the plain-language
outcomes (`FetchError`) and the four `/v1/fetch/jobs` routes
(`HttpFetchTransport`, which `DavCloud` and `RenewableCloud` expose as
`FetchTransport`). Like Admin and the update feed, every request is sent by
the sync worker over this device's certificate and skips the pause gate (not
file sync). The worker answers a `fetch` command beside its queue
(`answerFetchCommand`), so a poll neither waits for a pass nor makes the loop
send library state. `core/app/fetch_jobs.dart` (`FetchJobs`, reached as
`ClientController.fetchJobs`) holds availability (a 404 means absent),
the rows, polling every 2 s only while the tab and the app are visible and a
row is unfinished, a sync pass (`requestSyncPass`) when a poll sees rows
turn done (never twice for one row), the remembered choice in `<profile>/downloader.json`, and the link
parser.

The tab (F5) is `ui/downloader_tab.dart`: one scrollable with the form and
the job list, reading and calling `FetchJobs` only. `ClientHome` adds it as
a fourth tab while `availability` is `available`, replacing its
`TabController` when that changes (the selected library tab stays; a
Downloader that went away returns to Home), and hides the library toolbar on
it. It tells `FetchJobs` what is on screen: `setTabVisible` from the tab
controller (false while the first-sync screen replaces the home),
`setAppVisible` from `DesktopLifecycle.visible` on a desktop and
from `AppLifecycleState` (resumed) where there is no window lifecycle
(Android). Show in folder is the library's own reveal.
A window that is minimized, not hidden in the tray, still counts as on
screen: `DesktopLifecycle` knows only shown and hidden.

## How to add a platform

1. Create `lib/platform/<os>/` with a class for each port and an
   `<Os>PlatformAdapters implements PlatformAdapters`; add its branch to
   `lib/platform/adapters.dart`.
2. Implement the shared `anj_*` C ABI (`native/posix/exports.txt`) and bind
   it with `lib/platform/native/`, passing the library path and errno
   label. A POSIX platform builds `native/posix/rootfs.cc` with a
   `compat_<os>.h` of its primitives and its own guard and watch `.inc`
   files. Otherwise put native code in `native/<os>/` (exporting the same
   ABI), or implement `RootFilesystem` and `ReleaseGuard` directly. Check
   a POSIX build with `tool/native_test.sh` on that platform.
3. Add Flutter's runner (`flutter create --platforms=<os>`). Implement the
   `cloud.anj/window` channel (`show`, `hide`) for `WindowControl`, or return
   a different `WindowControl` from the session.
4. Implement `ChangeWatcherFactory` (`changeWatcher`, `watchReportsChanges`)
   in a class that imports no Flutter library, return it from both the
   adapter set and `lib/platform/watchers.dart`. `SyncEngine` starts and restarts its watcher only through them, passing
   a `WatcherSettings` (a restart passes the failed watcher's `settings`).
   Return null from `changeWatcher` where the platform or the given
   `RootFilesystem` has no usable watcher: the engine keeps the per-pass
   stat scan. A platform watcher binds its own native code; the Linux
   factory starts `LocalWatcher` only for its own `NativeRootFs`.
5. Work through the Linux assumptions below that affect the new platform.
   Keep Linux behaviour unchanged; the Linux tests must still pass.

## Left in place

This reorganization moved code without changing behaviour, so these
Linux-specific details remain in shared code:

- `RootTree` (`core/local/root_tree.dart`): `trustedFsMagic` (statfs magic
  numbers), writeback sysctls from `/proc/sys/vm` and the ctime probe.
  (Staging paths now come from the boundary: `RootFilesystem.stagePath`.)
- `RootFilesystem.watchScan` takes an opaque `Pointer<Void>` watch handle,
  `fsMagic` returns the statfs `f_type` (on Darwin a per-boot index that
  matches no Linux magic; S2's filesystem capabilities are not in M1), and
  `closeFd` is a function-typed getter (it was a `late final` FFI lookup).
  `EvictionNative` casts the port to `NativeRootFs`.
- `LocalWatcher` (Dart side) reads `/proc/self/mountinfo` and
  `/proc/self/fd`; on macOS both are absent and ignored (mounts beneath the
  root arrive as FSEvents Mount and Unmount events instead).
- `main()` parses the Linux manager's `--profile-lock-fd` and
  `--manager-command`. (A held profile is now `ProfileInUseException`, from
  the boundary's symbolic `wouldBlock`.)
- Linux errors carry `OSError('Linux errno', …)`; the label is a
  `NativeRootFs` parameter (`'macOS errno'` on macOS).
- Linux packaging and the manager stay in `tool/`. Two comments in
  `tool/linux_install.py` still name `lib/src/desktop_bus.dart` and
  `lib/src/root_tree.dart`; they are left as is so the shipped manager stays
  byte-identical.
- When the tray fails to start after the session bus opened, that bus
  connection is never closed (`LinuxDesktopSession.startTray`). This was
  already so before the move.

## macOS (spec #31)

M0 adds the macOS runner, the adapter skeleton and the mac-test seat
scripts. M1 adds the Darwin build of the native boundary and the root
filesystem adapter, M2 the FSEvents watcher, M3 the keychain, launcher,
desktop session (menu bar, Close to the menu bar, reopen, Quit), device
label, root location policy and App Nap. M6 adds the release archive and
receipt, the install manager and Start at login (below).

- **Runner** (`macos/`): generated by Flutter 3.47.9 and then configured.
  Bundle id `cloud.anj.anj-cloud` (fixed: keychain items, the LaunchAgent and
  privacy rows key on it), product "AnJ Cloud", arm64 only, minimum macOS 26.
  Ad-hoc signed ("Sign to Run Locally"), no sandbox. Release builds run with
  the hardened runtime and `disable-library-validation`: under the hardened
  runtime, library validation refuses every ad-hoc embedded framework
  ("different Team IDs"). Release carries no `get-task-allow`. Profile is

(`lib/platform/macos/macos_self_update.dart`), with the Linux contract:

- `installed` reads the bundle's `Contents/Resources/bundle-receipt.json`
  (target `macos-arm64`, version, version code); a build without one, such
  as a development build, offers no update.
- `check` and `handOver` run the manager embedded in the bundle (the copy
  `ManagerAutostart` runs): `apply-update <zip> --manifest <file> --check`
  before the offer, then detached `--result <file> --app-pid <pid>`, and

  receipt, and the archive's size and SHA-256. The archive's receipt must
  name the same version code and target. The installed bundle's seal is
  checked first (`codesign --verify`), since it vouches for the update.
- It then waits for the app to quit (2 minutes) and runs this same
  journalled `update` from the verified copy with `--window`. The outcome
  goes to `<profile>/updates/result.json`, which the app reads (and
  clears) as it starts, so it is written before the release that will
  read it starts: the update writes "updated" just before launching the
  new release, and a failed launch check replaces it with the failure

  release before, which is started instead. Installed or refused, the download is deleted. The
  manager runs from a private copy of itself, because it replaces the
  bundle it lives in.

  and zips it. `deploy/release.py publish --target macos-arm64 --artifact

- `tool/macos/verify_update_reference.py` is the verifier's Python
  reference. `tool/macos/test_manager.sh` runs it as the fake app's
  verifier for the tamper cases on the VM host (Python 3.11+; skipped where there

**FSEvents watcher (M2).** One recursive stream on the root
(`FileEvents|NoDefer|WatchRoot`) starts when the root itself is watched,
which `MacosChangeWatchers` does before returning the watcher; its latency
is the quiet period (`anj_watch_latency`, a no-op on Linux), so a change
reaches a pass within quiet plus the maximum delay. Every other
`anj_watch_add`/`remove` is bookkeeping (a path gets a watch descriptor).
Events become the same compact records as inotify's, with inotify mask
bits, so the shared `LocalWatcher` runs unchanged: an item event is a record
on its watched parent (or a subtree record on the nearest watched ancestor);
`MustScanSubDirs` and the drop flags are a subtree record, or `IN_Q_OVERFLOW`
at the root (the full audit); `RootChanged` is `IN_MOVE_SELF` on the root
(the root self-audit); Mount and Unmount audit the mount point. Renames carry
no cookie, so each side is queued alone and reconciled by stat: a macOS
rename is seen as a delete plus a create, and its identity is resolved by
the engine's scan (not paired by inode in the watcher). Suspend is
`CLOCK_MONOTONIC_RAW - CLOCK_UPTIME_RAW`. #39's stamp fast path stays off
on macOS (writeback parameters unknown); instead, with the watcher attached,
hashing is event-driven (decision #135, below). `watchReportsChanges` is true only
on APFS (the `u` volume key). `anj_watch_debug_inject` with a watch
descriptor injects an FSEvents event with the given flags (tests).

**Scan cost (decision #135, flag SC-051).** Two shared switches, both off
on Linux:

- *Event-driven hashing.* `RootFilesystem.fullVerificationInterval` (null on
  Linux and Windows; 60 minutes from the macOS adapter, 15 minutes when
  Android adopts it, #130 (3)). With it, no trusted stamps and a working
  watcher, `SyncEngine.eventDriven` holds: an ordinary pass hashes only the
  paths the watcher reported and new entries beneath them, subtree rescans
  reuse a hash whose scan stamp is unchanged, and a paused check is
  stat-only. A full verification pass hashes every file at start, after lost
  events (a drop or MustScanSubDirs at the root, RootChanged, a suspend),
  when a dead watcher restarts, on `requestFullVerification` and at the
  interval; while the watcher is dead every pass is full. Between
  verifications a stat-only audit of the whole root runs every 5 minutes and
  reads only files whose stat stamp changed (#137 (3)). After a pass that
  found nothing (and did not throw) the worker waits for the cloud listing,
  not its 2 s timer.
- *Exact names (#137 (2)).* APFS resolves a path case- and
  normalization-insensitively, so a stat of the old name of a case-only
  rename still succeeds. `anj_watch_scan` of a single path reports the
  stored spelling (`stored_path` in `compat_darwin.h`, `ATTR_CMN_NAME` per
  component; identity on Linux) when it differs, without walking or
  watching it, and `RootTree` then treats the requested path as gone; the
  stored spelling arrives by its own event. An event-driven pass can see
  the old spelling vanish before the watcher delivers the new one, so it
  infers a removal only after the path has been missing for the quiet
  period and no other spelling of it is queued (`ChangeWatcher.pending`);
  #71's pairing (decision #138) then plans the move.
- *Grouped manifest commits.* `CommitDurability`
  (`core/ports/commit_durability.dart`, selected by
  `lib/platform/durability.dart`; `MacosCommitDurability` on macOS, none
  elsewhere). SQLite commits with a plain fsync, each commit is then ordered
  by `F_BARRIERFSYNC` before `save()` returns, and `Manifest.commitPoint`
  makes every pending commit durable with one `F_FULLFSYNC`: after 64
  commits, at every pass end, on a settings write, on close, and before
  every destructive root change (#137 (1)): the binding's quarantine,
  rename and empty-folder removal and the release guard's preserve,
  quarantine and unlink call `RootFilesystem.beforeDestructiveChange`, which
  the engine sets to `commitPoint`, so no root change that would read as a
  local delete can become durable before its record, whatever the volume.
  Checkpoints stay `F_FULLFSYNC`. A process crash loses nothing; a power
  loss loses at most the additive work since the last flush, which is
  redone. A refused barrier or flush returns the manifest to a durable
  commit each time; the pending commits are then made durable by a full
  checkpoint at the next commit point, which throws rather than let a
  destructive change proceed undurably.

**Release guard (decision #42, weaker than Linux).** The guard holds an
`O_EVTONLY` descriptor (it reads like `O_RDONLY` but never makes the file
"busy") and records inode, links, size, mtime, ctime and birth time. At
guard open and before a quarantine rename it asks the kernel which
processes hold the file open or mapped (`proc_listpidspath`, event-only
descriptors excluded) and refuses with EBUSY, so a busy file is refused
before anything moves, as the Linux lease does. Every step requires the
recorded stamp; only the guard's own renames and link removals may move
ctime and the link count. The last link is removed with
`unlinkat(AT_NODELETEBUSY)`, which fails with EBUSY while any descriptor or
mapping remains, whoever holds it. Unlike the lease, a process that opens,
reads and closes the file inside the window is not seen; a write moves
mtime and ctime and fails the release. The in-use query lists only
processes this user may inspect; the final unlink check covers everyone.

What the engine does with each outcome (M4, `test/release_guard_qualification_test.dart`,
the same file on Linux and on mac-test): a descriptor in the app, a shared
mapping whose descriptor is closed, or a descriptor held only by a child
process refuses the release before anything moves, and the file stays at
its path, pending, until the holder lets go. An open that starts after the
quarantine fails the final unlink (`AT_NODELETEBUSY`): the remote-verified
bytes stay in private staging, pending, and the next pass after the holder
closes completes the release (they are not moved back to the path). A
write between the hash and the unlink fails the release and keeps the
written bytes as a recovery copy with a conflict (Recover). A clean release
frees the bytes and the remote copy is unchanged. The adapter reports
`busyAndUnchanged` (decision #126); the Linux lease reports `lease`.

**Editor round trip (M4, row 14).** `tool/editor_roundtrip_fixture.dart`
edits a txt, an rtf and a pdf in a Local folder (in place) and in a Cloud
folder (as an editor working copy from Open), then confirms Finish
editing, against the disk-backed fixture cloud; it records every new name
an editor leaves beside the file. On the VM host it runs with an atomic-save stand-in
(`test/editor_roundtrip_fixture_test.dart`); on mac-test `tool/macos/check_m4.sh`
drives TextEdit and Preview (its save path only; annotation is the operator's at M7)
through `osascript` only where
`automation_consent.swift` finds Automation consent without prompting. Any
